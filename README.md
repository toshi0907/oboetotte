# oboetotte

スマートフォンのみで開発するAndroid向けTodoアプリです。

- 実装: Kotlin + Jetpack Compose
- データ保存: 主データは端末内(Room / SQLite)のみ。共同編集は非対応。バックアップコピーはローカル・クラウド(SAFフォルダ)へZIP形式で書き出し可能
- ビルド: GitHub Actions
- 開発フロー: GitHubでコード管理 → Claude Codeで実装 → GitHub ActionsでAPKビルド → 端末にインストールして動作確認

## 実装済みの機能

- タスクの登録・完了チェック・編集・削除(タスク行をタップするとまず読み取り専用の確認画面が開き、上部の「編集」ボタンから編集画面に進む。登録時は期限日時が自動で1時間後に設定される〈サブタスクも同様〉)
- 期限日時の設定(一覧で期限切れは赤系、当日が期限のタスクは緑系で色分け表示)。カレンダー・時刻ピッカーのほか、「5分後」「15分後」「30分後」「1時間後」「3時間後」「6時間後」「1日後」「1週間後」「1ヶ月後」のクイック選択も可能
- 一覧の並び替え(未完了優先・期限が近い順)、完了済みタスクの表示/非表示切り替え
- リスト(プロジェクト)によるタスクの分類。一覧の絞り込みは「すべて」「リスト未登録」(どのリストにも属さないタスクのみ)+各リストから選択
- 表示フィルタ(「リンクを含む」「未完了で、期限が今日または期限切れ」の2種類を用意し、複数選択可能〈選択中はOR条件、いずれか1つでも合致すれば表示〉。トップレベルのタスクにのみ適用し、条件に合致したタスクはそのサブタスクツリーごと表示)
- サブタスク(チェックリスト、多階層ネスト対応。メイン画面・編集ダイアログの両方でインデント付きツリー表示)
- 繰り返しタスク(毎日・毎週・毎週(曜日を複数選択)・毎月。完了すると次回分を自動生成)
- リマインダー通知(期限日時に通知。端末再起動後も再スケジュール。設定画面の「テスト通知」ボタンで動作確認可能。通知から完了、または「スヌーズ」ボタンから15分後/30分後/1時間後/3時間後/1日後のいずれかを選んでスヌーズ可能。タスクごとに「オートスヌーズ」〈なし/15分/30分/1時間/3時間/1日〉を設定でき、通知後に未完了のまま指定間隔が経過すると、完了するまで上限なく自動で再通知を繰り返す。手動でスヌーズを選んだ場合はその時刻を基準に次回のオートスヌーズが計算し直される)
- 通知のみタスク(タスクごとに個別設定。通知されること自体が重要で完了確認が不要なタスク向けに、期限日時通知を実際に表示できた時点で自動的に完了になる。通知に「完了」「スヌーズ」ボタンは出さず、オートスヌーズとも併用不可。繰り返しタスクなら通知のたびに次回分がそのまま生成される)
- 位置情報リマインダー(住所入力または現在地で場所を登録し、指定した半径への到着・離脱で通知。期限日時リマインダーとは独立した機能。GPS誤差による一瞬だけの誤検知で通知が飛ばないよう、状態が3分間継続した場合のみ通知するデバウンスあり)。「自宅」「職場」などの場所をあらかじめ登録しておき、通知設定時に選択することも可能。到着・離脱の確認方式は設定画面から「Geofencing API」(端末標準、省電力)と「連続追跡方式」(1〜60分間隔〈既定15分〉で自前に位置取得し続け検知が速く正確、バッテリー消費は増える)から選択可能
- タスクへのURL・メモの追加(URLを登録すると通知に「リンクを開く」ボタンが表示されタップで開ける。メモはタスクを開くと表示・編集できる自由記述の文字列)
- タスクへのファイル添付(任意の形式のファイルを複数添付可能。端末内にコピーして保存するため元ファイルが後から削除されても残る。追加時は「全ファイルから選択」「写真から選択」〈標準のフォトピッカーで画像のみ〉を選べる。一覧は画像をサムネイル表示、タップで外部アプリから開ける。タスクの確認画面では、画像・PDFはその場でインラインプレビュー表示〈PDFは全ページ縦スクロール、背景は白固定〉。繰り返しタスクでは添付ファイルが同じ繰り返しシリーズの全インスタンス〈過去の完了済み分を含む〉で共有され、完了して次回分が生成されても消えず、どのインスタンスから追加・削除しても連動する)
- ローカルバックアップ(ZIP形式でのエクスポート/インポート。添付ファイルの実体も含めて復元可能。設定画面から実行)
- クラウド自動バックアップ(Storage Access Frameworkでフォルダを選択するだけで、Dropbox等のクラウドストレージアプリ内のフォルダにも毎日1回自動でバックアップ〈ローカルバックアップと同じZIP形式〉できる。APIキーやOAuth認証は不要。保存時刻は設定画面から任意の時刻〈既定は午前3時〉に変更可能。保持件数〈既定7件〉を超えた古いバックアップは自動削除。「今すぐバックアップ」による手動実行や、最終実行結果の確認も設定画面から可能)
- 通知履歴(デバッグ用。期限日時通知・位置情報通知〈スヌーズ経由の再通知を含む〉が実際に発火するたびに、発動時刻・タスク名・トリガとなった条件を記録し、設定画面から一覧確認できる。直近200件を超えると古いものから自動削除)
- 位置情報の更新履歴(デバッグ用。ジオフェンスの到着・離脱イベント受信〈通知の表示可否に関わらず、通知をスキップした理由も含めて記録。登録座標からの距離・半径も記録し、圏内のまま誤検知したケースを直接判別可能〉と、5分間隔で取得するバックグラウンドの現在地〈位置情報を使う未完了タスクがある間のみ動作〉の両方を記録し、位置情報デバッグ画面から一覧確認できる。直近6時間を超えると古いものから自動削除)
- 設定画面(メイン画面の「設定」ボタンから遷移する全画面。アップデート、リストの編集、保存済みの場所の編集、位置情報リマインダーの確認方式・更新頻度、バックアップ、クラウド自動バックアップ、テスト通知・位置情報デバッグ・通知履歴等のデバッグ機能、の順にまとめて表示)
- アプリ内アップデート(Google Playを使わず配布しているため、GitHubの`latest-debug`リリースを見に行き新しいビルドがあるかを起動時に自動チェック。アプリを開いていない間もバックグラウンドで6時間おきに定期チェックし、更新があれば通知。更新があれば一覧画面上部にバナー表示、または設定画面から手動チェック・確認も可能。設定画面には直近の確認時刻も表示。ダウンロード中はボタンが「ダウンロード中…」表示になり無効化されるため、インストールダイアログが出るまでの間も操作中であることが分かる。ダウンロードしたAPKはシステムのインストーラーで確認の上インストール)
- ホーム画面ウィジェット(未完了タスクを期限が近い順に一覧表示。各項目にはタイトルに加え期限〈あれば。メイン画面と同じく期限切れは赤系・当日期限は緑系で色分け〉・リンク〈URLがあればボタン状で表示〉も表示。行をタップするとアプリが開き、リンクボタンをタップするとブラウザ等でURLを直接開く。タスクの追加・完了・編集・削除のたびに自動で更新。背景色は「透過」「白」「黒」から、表示するリストは「すべて」「リスト未登録」+各リストから、表示フィルタはメイン画面と同じ「リンクを含む」「今日期限・期限切れ」〈複数選択可〉から、ウィジェットを追加する際にウィジェットごとに個別選択可能)
- 共有によるタスク追加(他のアプリの共有メニューからOboetotteを選ぶと、確認画面無しで「タスク(年/月/日 時:分)」という名前の新規タスクを即座に作成。共有した写真・ファイル〈複数選択時はまとめて1タスクに〉はそのタスクの添付ファイルとして保存され、共有したテキストはURL形式であればそのタスクのURLに、それ以外の文章であればメモに保存される〈ファイルとテキストを同時に共有した場合は両方とも保存〉。期限は他のタスク登録と同様デフォルトで1時間後に設定される)

## アプリのインストール方法

### 方法1: GitHub Releaseから(推奨)

`latest-debug` というタグに、`main` ブランチへのpushのたびに最新(マージ済み)のデバッグAPKが自動で添付されます。他のブランチへのpushではビルドの成否のみ確認され、このタグは更新されません。

1. [Releaseページ](https://github.com/toshi0907/oboetotte/releases/tag/latest-debug)を開く
2. `app-debug.apk` をダウンロード
3. スマホの設定で「提供元不明のアプリ」のインストールを許可し、APKをタップしてインストール

デバッグ用の署名鍵は固定しているため、2回目以降は上書きインストールできます。

### 方法2: GitHub Actionsのartifactsから

`main` ブランチや各ブランチへのpush、Pull Request作成時に `.github/workflows/android-build.yml` が自動実行され、デバッグ用APKがビルドされます。

1. GitHubリポジトリの「Actions」タブを開く
2. 該当のワークフロー実行(Android Build)を開く
3. 「Artifacts」欄の `app-debug` をダウンロード(zip形式)
4. 展開して出てくる `app-debug.apk` をスマホに転送してインストール

Artifactは90日で失効するため、通常は方法1のReleaseを使うことを推奨します。

手動でビルドを実行したい場合は、Actionsタブから「Android Build」ワークフローを選び「Run workflow」で実行できます。

## プロジェクト構成

```
app/
  src/main/java/com/toshi0907/oboetotte/       アプリのKotlinソースコード
    attachment/                                  タスクの添付ファイルの実体をfilesDir配下に保存(AttachmentStorage)
    backup/                                      ローカル/クラウド自動バックアップ(ZIP export/import、SAF経由のクラウドフォルダへの定期実行)
    data/                                       Room(Task, TaskList, TaskAttachment, DAO, Database)
    notification/                                リマインダー通知(AlarmManager, BroadcastReceiver)
    widget/                                      ホーム画面ウィジェット(Jetpack Glance)
    ui/theme/                                    Compose Material3テーマ
  src/main/res/                                 リソース(文字列・アイコン等)
.github/workflows/android-build.yml             GitHub ActionsによるAPKビルド・Release更新
```

## ローカルでのビルド(参考)

Android Studioやローカル環境がある場合は以下でもビルド可能です。

```
./gradlew assembleDebug
```
