# 期限ピッカー・DBマイグレーション

期限は`DatePickerDialog`+`TimePicker`(いずれも`@ExperimentalMaterial3Api`)を連続で開いて設定・クリアでき、`DatePicker`が返す`selectedDateMillis`はUTC 0時のepoch millisなので、選択した時刻と合成する際は`combineDateAndTime()`(`MainActivity.kt`内のプライベート関数)でローカルタイムゾーンに変換しています。`EditTaskDialog`の「設定」ボタンをタップして期限ピッカーを開いた時点でまだ期限(`dueAt`)が未設定の場合、`DatePicker`の初期選択日は`todayAsDatePickerMillis()`(端末のローカルタイムゾーンでの「今日」をUTC 0時基準のepoch millisに変換するプライベート関数)、`TimePicker`の初期時刻は`LocalTime.now()`となり、いずれも現在日時がデフォルト表示されます(既に`dueAt`が設定済みの場合は、その日時をそのまま初期値として表示します)。この挙動はタスク追加時のデフォルト値(`TaskViewModel.addTask`/`addSubtask`が設定する登録時刻の1時間後、`docs/architecture/task-viewmodel.md`参照)とは無関係です。**期限のクイック選択**: 「設定」/「クリア」ボタンの下に`DUE_QUICK_OPTIONS`(`MainActivity.kt`内、ラベルと「タップ時点の現在時刻(epoch millis)→期限(epoch millis)」を計算する関数`(Long) -> Long`のペアのリスト。5分後/15分後/30分後/1時間後/3時間後/6時間後/1日後/1週間後/1ヶ月後)ぶんの`AssistChip`を並べており、タップすると`dueAt`に計算結果を直接セットします(カレンダー/時刻ピッカーを介さない簡易入力)。日・週は固定長のため`addMinutes()`で分加算するだけですが、月は日数が28〜31日と変動するため`addMonths()`で`java.time`の`plusMonths(1)`によるカレンダー月単位の加算を行います(`TaskCompletion.nextDueAt`の繰り返しタスクの月加算と同じ考え方)。他の項目と同様にダイアログ内の状態を書き換えるだけで、「保存」ボタンを押すまでDBには反映されません。**DBマイグレーション**: `AppDatabase`はバージョン6以降、明示的な`Migration`オブジェクト(`MIGRATION_6_7`〜`MIGRATION_10_11`、`AppDatabase.kt`内の`companion object`に定義)で`ALTER TABLE`/`CREATE TABLE`のSQLを直接実行し、アプリ更新時に端末内のデータを保持したままスキーマを更新します(以前は`fallbackToDestructiveMigration()`のみでデータが破棄されていましたが、実運用でのデータ消失が問題になったため導入しました)。**エンティティのスキーマを変更する際は、`@Database`の`version`を上げるのに加えて、必ず新しいバージョンへの`Migration`を追加し`addMigrations()`に登録してください。** 追加を怠ると、そのバージョン間で更新したユーザーのデータが失われます。`fallbackToDestructiveMigration()`は、対応する`Migration`が定義されていない古いバージョン(6より前)からの更新時のみ働く最終手段として残しています。
