# 位置情報リマインダー

**位置情報リマインダー**: `com.google.android.gms:play-services-location`(`app/build.gradle.kts`に追加。`google()`リポジトリ経由なので既存のAndroidX依存と同じくローカルサンドボックスでは解決できずGitHub Actionsでのみビルド確認可能)の`FusedLocationProviderClient`を使い、期限日時リマインダーとは独立した別機能として実装しています。到着・離脱の検知はGoogle Play servicesのGeofencing APIには任せず、フォアグラウンドサービスで一定間隔ごとに自前で位置を取得して判定する**連続追跡方式のみ**です(詳細は`docs/architecture/location-tracking-mode.md`。以前はGeofencing APIとの切り替え式でしたが、端末側で評価が間引かれ数時間遅れて通知される問題があったため廃止しました)。`EditTaskDialog`の「位置」セクションで、住所文字入力(`geocodeAddress()`、`LocationLookup.kt`内のトップレベル関数。`android.location.Geocoder`を使い、位置情報の権限は不要)または「現在地を使う」ボタン(`getCurrentLocationResult()`、同ファイル内。`FusedLocationProviderClient.getCurrentLocation`を使い、`ACCESS_FINE_LOCATION`権限が必要)のいずれかで場所を1件登録し、半径(100m/300m/500m/1km)と通知タイミング(到着時・離脱時をタスクごとに個別選択、両方も可)を設定します。位置が未設定なら通知タイミングも未設定のままで良い一方、位置を設定した場合は到着・離脱のどちらか一方以上を選ばないと保存ボタンが無効化されます。`notification/LocationReminderManager`(`register`/`unregister`)が登録・解除を担当し、`TaskViewModel`の`updateTask`・`toggleDone`(繰り返しタスクの次回生成分を含む)・`deleteTask`、および`TaskCompletion.complete`から呼び出されます。位置情報を使う未完了タスクが1件以上あれば`LocationTrackingService`を起動し、無くなれば停止します。登録には`ACCESS_FINE_LOCATION`に加えAPI 29(Q)以降は`ACCESS_BACKGROUND_LOCATION`も必要で(`LocationReminderManager.hasLocationPermission`で両方を確認)、権限が無ければ登録をスキップします。位置情報を使うタスクが1つ以上あるのに権限が不足している場合、メイン画面に権限バナーを表示し、タップすると`Settings.ACTION_APPLICATION_DETAILS_SETTINGS`でアプリ設定画面へ誘導します(この画面から「常に許可」を選べば両方の権限が一度に付与されます)。**通知のデバウンス**: GPS/ネットワーク測位の精度が低いタイミングでは、実際には動いていなくても圏内/圏外の判定が一瞬だけ反転することがあります(特に半径に対して精度〈`Location.accuracy`〉が粗い場合や、複数の円が近接・重複している場合に起きやすい)。これを避けるため、`LocationTrackingService`は遷移を検知しても即座に通知せず、対象タスクがその遷移方向を望んでいる場合に限り`GeofenceConfirmWorker.schedule(context, taskId, isEnter)`を呼んでデバウンスします。`GeofenceConfirmWorker`(`CoroutineWorker`)は`WorkManager.enqueueUniqueWork`を`ExistingWorkPolicy.REPLACE`・ユニークワーク名`"geofence_confirm_<taskId>"`で使うため、同じタスクに対してデバウンス時間内(既定`GeofenceConfirmWorker.DEBOUNCE_DELAY_MINUTES`=3分)に別のイベント(同方向・反対方向を問わず)が届くと、以前の実行はキャンセルされ新しいイベントのタイマーに置き換わります。つまり実際に通知が確定するのは「最後に検知した遷移から3分間、後続の遷移が無かった」場合のみで、`doWork`実行時にタスクの状態(完了済みでないか・通知タイミングを希望しているか)を再確認してから、期限日時通知とは別の通知チャンネル`location_reminders`で通知を表示する処理(`notification/LocationReminderNotifier.showNotification`)を呼びます(通知IDは期限日時通知〈`ReminderReceiver`〉と同じ`taskId.toInt()`を使いますが、通知タグは別〈`NOTIFICATION_TAG_LOCATION`、詳細は`docs/architecture/reminder-notifications.md`〉のため、同じタスクに期限日時リマインダーも設定されていて両方が発火しても、互いを上書きせず両方とも通知欄に表示されます。「完了」ボタン〈`CompleteReceiver`〉はどちらの通知でも正しく消去できます)。端末再起動後は`BootReceiver`が`taskDao.getPendingWithLocation()`の全件を`LocationReminderManager.register`で再登録します(=サービスを再起動します)。アプリ更新直後も、アプリを開くまでサービスが止まったままにならないよう、`BootReceiver`が`ACTION_MY_PACKAGE_REPLACED`を受けて`LocationReminderManager.reconcileAll`を呼びます(期限日時のアラームは更新を越えて保持されるため、この経路では再スケジュールしません)。バックアップのJSON形式にも位置情報の各フィールドが含まれます。完了・削除・位置設定の解除以外では登録は解除されないため、エリア外→エリア内を繰り返すたびに何度でも通知される設計です(1回きりの通知ではありません)。**旧バージョンからの移行**: 旧バージョンでGeofencing APIへ登録したジオフェンスは端末側(Play services)に残り続けるため、`LocationReminderManager.reconcileAll`(アプリ起動時・アプリ更新時・位置情報の権限が新たに許可された時に呼ばれる)の冒頭で一度だけ`removeLegacyGeofencesLocked`が一括解除します。旧バージョンは全ジオフェンスで同じ`PendingIntent`(削除済みの`GeofenceReceiver`宛て、requestCode 0)を共有していたため、クラス名文字列で同一視される`PendingIntent`を作り直し、`GeofencingClient.removeGeofences(PendingIntent)`で解除します。成功したら`LocationTrackingSettings.markLegacyGeofencesRemoved`で完了フラグを立て、失敗時やPlay servicesが10秒以内に応答しない場合(`withTimeoutOrNull`。応答待ちで`Mutex`を保持し続けて他の登録・解除を止めないため)はフラグを立てず次回の`reconcileAll`で再試行します。廃止した確認方式設定のキー`mode`は解除の成否と関係なく`clearLegacyMode`で削除します。解除前に旧ジオフェンスが発火しても、受信先の`GeofenceReceiver`が存在しないため何も起きません。設定画面(`SettingsScreen`)の「位置情報デバッグ」ボタンから`LocationDebugDialog`を開くと、位置情報の権限状態(前面/常に許可)、「現在地を取得」ボタンによる現在地の座標、位置情報を設定した各タスクの登録座標・半径・通知タイミング・現在地からの距離と圏内/圏外を確認できます(タスクのフィールド値と権限状態から推測した表示です)。
