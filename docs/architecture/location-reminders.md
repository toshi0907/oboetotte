# 位置情報リマインダー

**位置情報リマインダー**: `com.google.android.gms:play-services-location`(`app/build.gradle.kts`に追加。`google()`リポジトリ経由なので既存のAndroidX依存と同じくローカルサンドボックスでは解決できずGitHub Actionsでのみビルド確認可能)のGeofencing APIを使い、期限日時リマインダーとは独立した別機能として実装しています。`EditTaskDialog`の「位置」セクションで、住所文字入力(`geocodeAddress()`、`LocationLookup.kt`内のトップレベル関数。`android.location.Geocoder`を使い、位置情報の権限は不要)または「現在地を使う」ボタン(`getCurrentLocationResult()`、同ファイル内。`FusedLocationProviderClient.getCurrentLocation`を使い、`ACCESS_FINE_LOCATION`権限が必要)のいずれかで場所を1件登録し、半径(100m/300m/500m/1km)と通知タイミング(到着時・離脱時をタスクごとに個別選択、両方も可)を設定します。位置が未設定なら通知タイミングも未設定のままで良い一方、位置を設定した場合は到着・離脱のどちらか一方以上を選ばないと保存ボタンが無効化されます。`notification/LocationReminderManager`(`register`/`unregister`)がジオフェンス(requestId=タスクIDの文字列表現)の登録・解除を担当し、`TaskViewModel`の`updateTask`・`toggleDone`(繰り返しタスクの次回生成分を含む)・`deleteTask`、および`TaskCompletion.complete`から呼び出されます。ジオフェンスの登録には`ACCESS_FINE_LOCATION`に加えAPI 29(Q)以降は`ACCESS_BACKGROUND_LOCATION`も必要で(`LocationReminderManager.hasLocationPermission`で両方を確認)、権限が無ければ登録をスキップします。位置情報を使うタスクが1つ以上あるのに権限が不足している場合、メイン画面に権限バナーを表示し、タップすると`Settings.ACTION_APPLICATION_DETAILS_SETTINGS`でアプリ設定画面へ誘導します(この画面から「常に許可」を選べば両方の権限が一度に付与されます)。`notification/GeofenceReceiver`が到着・離脱イベントを受け取ります。**通知のデバウンス**: GPS/ネットワーク測位の精度が低いタイミングでは、実際には動いていなくてもジオフェンスの内外判定が一瞬だけ反転し、ENTER/EXITが誤って発火することがあります(特に半径に対して精度〈`Location.accuracy`〉が粗い場合や、複数のジオフェンスの円が近接・重複している場合に起きやすい)。これを避けるため、`GeofenceReceiver`はイベントを受け取っても即座に通知せず、対象タスクが未完了かつそのタスクが該当する遷移方向を望んでいる場合に限り`GeofenceConfirmWorker.schedule(context, taskId, isEnter)`を呼んでデバウンスします。`GeofenceConfirmWorker`(`CoroutineWorker`)は`WorkManager.enqueueUniqueWork`を`ExistingWorkPolicy.REPLACE`・ユニークワーク名`"geofence_confirm_<taskId>"`で使うため、同じタスクに対してデバウンス時間内(既定`GeofenceConfirmWorker.DEBOUNCE_DELAY_MINUTES`=3分)に別のイベント(同方向・反対方向を問わず)が届くと、以前の実行はキャンセルされ新しいイベントのタイマーに置き換わります。つまり実際に通知が確定するのは「最後に受信したイベントから3分間、後続のイベントが来なかった」場合のみで、`doWork`実行時にタスクの状態(完了済みでないか・通知タイミングを希望しているか)を再確認してから、期限日時通知とは別の通知チャンネル`location_reminders`で通知を表示する処理(`notification/LocationReminderNotifier.showNotification`、`GeofenceReceiver`から切り出した共通処理)を呼びます(通知IDは期限日時通知〈`ReminderReceiver`〉と同じ`taskId.toInt()`を使いますが、通知タグは別〈`NOTIFICATION_TAG_LOCATION`、詳細は`docs/architecture/reminder-notifications.md`〉のため、同じタスクに期限日時リマインダーも設定されていて両方が発火しても、互いを上書きせず両方とも通知欄に表示されます。「完了」ボタン〈`CompleteReceiver`〉はどちらの通知でも正しく消去できます)。ジオフェンスは端末再起動で失われるため、`BootReceiver`が`taskDao.getPendingWithLocation()`の全件を`LocationReminderManager.register`で再登録します。バックアップのJSON形式にも位置情報の各フィールドが含まれます。`GeofencingRequest`の`initialTrigger`は「到着時」が有効な場合のみ`INITIAL_TRIGGER_ENTER`を指定しており、登録した時点で既に圏内にいればすぐに通知が届くため動作確認がしやすくなっています(離脱のみの場合は初回トリガー無し)。ジオフェンスは完了・削除・位置設定の解除以外では解除されないため、エリア外→エリア内を繰り返すたびに何度でも通知される設計です(1回きりの通知ではありません)。ただしGeofencing APIのデフォルトの通知応答性は数分単位と粗く、特に小さい半径ではGPS誤差でEXITが検知されずその後のENTERも漏れることがあるため、`GeofencingRequest.Builder.setNotificationResponsiveness()`で`NOTIFICATION_RESPONSIVENESS_MILLIS`(60秒)を指定し、再突入の検知を速めています。`addGeofences`の成功/失敗、および`GeofenceReceiver`が実際に受信したジオフェンスイベント(ENTER/EXITの種別・対象requestId・デバウンス予約の可否)は`Log`(タグ`LocationReminder`)に出力するので、繰り返し通知されない場合はlogcatで「イベント自体が来ていないのか」「来ているが条件(完了済み/通知タイミング未選択)で弾かれているのか」「デバウンス中に反対方向のイベントで打ち消されたのか」を切り分けられます。設定画面(`SettingsScreen`)の「位置情報デバッグ」ボタンから`LocationDebugDialog`を開くと、位置情報の権限状態(前面/常に許可)、「現在地を取得」ボタンによる現在地の座標、位置情報を設定した各タスクの登録座標・半径・通知タイミング・現在地からの距離と圏内/圏外を確認できます(実際にOS側へ登録済みかどうかを直接問い合わせるAPIは無いため、あくまでタスクのフィールド値と権限状態から推測した表示です)。
