# 設定画面(SettingsScreen)

**設定画面(`SettingsScreen`)**: 「設定」`AssistChip`から遷移する全画面です。以前メイン画面のチップに散らばっていた補助的な操作(リストを編集・場所を編集・テスト通知・位置情報デバッグ)と、既存のバックアップ(エクスポート/インポート)をここに集約しています。セクションは上から「アップデート」(アプリ内アップデート、詳細は`docs/architecture/app-update.md`)・「リスト」(「リストを編集」から`ManageListsDialog`。リストの追加・改名・削除)・「場所」(「場所を編集」から`ManageLocationsDialog`。保存済みの場所の管理)・「位置情報」(位置情報リマインダーの確認方式、詳細は`docs/architecture/location-tracking-mode.md`)・「バックアップ」(従来`SettingsDialog`だった内容。説明文+「エクスポート」「インポート」ボタンをそのままインライン表示)・「クラウド自動バックアップ」(詳細は`docs/architecture/cloud-backup.md`)・「AI連携」(詳細は`docs/architecture/ai-gemini.md`)・「デバッグ」(「テスト通知」ボタン・「位置情報デバッグ」ボタン〈`LocationDebugDialog`を開く〉・「通知履歴」ボタン〈`NotificationLogDialog`を開く。詳細は`docs/architecture/notification-log.md`〉・「AIテスト実行」ボタン)、の順に並びます。ボタンをタップして開く`ManageListsDialog`/`ManageLocationsDialog`/`LocationDebugDialog`/`NotificationLogDialog`自体は従来どおりダイアログのままで、`SettingsScreen`という1枚の全画面から呼び出す形になっています。新機能を追加する際、それがメイン画面での日常的な操作ではなく設定・管理・デバッグの類であれば、メイン画面のチップを増やすのではなくこの`SettingsScreen`にセクションを追加してください。**新しいセクション・項目をこの画面に追加する際は、挿入位置(どのセクションの前後に置くか)をユーザーに確認してから追加してください。上記の並び順を含め、セクションの並び順はユーザーの日常的な利用頻度・優先度を反映した意図的なものであり、Claude Codeの判断だけで並び順を変更・追加しないこと。**「アップデート」セクションには、現在のビルド(`BuildConfig.GIT_COMMIT_SHA`)・直近の更新チェック時刻(`updateLastCheckedAt`。`update/AppUpdateCheckSettings`にSharedPreferencesで永続化し、アプリ起動時の自動チェック・この画面の「更新を確認」ボタン・バックグラウンドの定期チェック〈`AppUpdateCheckWorker`〉のいずれで更新した時刻も反映)・チェック結果に応じた文言・「更新を確認」ボタンを表示します。「ダウンロードしてインストール」ボタン(`TaskScreen`側のバナーにある「更新する」ボタンも同様)は、APKのダウンロードにインストールダイアログが表示されるまで時間がかかりタップできたかどうか分かりづらいことがあったため、ダウンロード中は`isDownloadingUpdate`により無効化しつつラベルを「ダウンロード中…」に変えて処理中であることを示します。
