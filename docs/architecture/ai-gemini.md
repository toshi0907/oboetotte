# AI連携(Gemini)

**AI連携(タスク通知へのGemini要約)**: `app/src/main/java/com/toshi0907/oboetotte/ai/`に`GeminiSettings`(APIキー・使用モデルをSharedPreferences`gemini_settings`で永続化)・`GeminiClient`(Gemini APIの`generateContent`呼び出し)を置いています。リポジトリはpublicなためAPIキーはコード・ビルド設定に一切含めず、ユーザー自身が発行したキーを設定画面(`SettingsScreen`)の「AI連携」セクションで入力し端末内にのみ保存する運用です。同セクションではモデル(`GeminiModel`列挙、`gemini-2.5-flash`/`gemini-2.5-flash-lite`〈既定〉/`gemini-3.5-flash-lite`の無料枠があるFlash系のみを候補にした`FilterChip`選択)も選べます。Geminiのモデルは数ヶ月単位で廃止される入れ替わりが速く(例: `gemini-2.0-flash`は2026年6月1日付で廃止済みのため候補から削除し、`GeminiModel.fromName`で保存済みのその値を`DEFAULT`へ読み替える互換処理を残しています)、候補・既定値は今後も見直しが必要です。`GeminiClient`は`AppUpdateChecker`と同じ方針で追加ライブラリ(Google AI SDK)を使わず`HttpURLConnection`+`org.json`の素のHTTP POSTで実装しています。`EditTaskDialog`の「メモ」直下に任意項目「AIプロンプト」(`Task.aiPrompt`)があり、設定したタスクは期限日時の通知(`ReminderReceiver`)が発火するタイミングでのみ(位置情報通知は対象外)、`aiPrompt`とAPIキーの両方が設定されていればGeminiへ問い合わせ、結果を`NotificationCompat.BigTextStyle`で通知本文に追記します。`ReminderReceiver`は`BroadcastReceiver`のためネットワークI/Oを直接実行できず、既存の`goAsync()`+`Dispatchers.IO`の経路(`docs/architecture/reminder-notifications.md`参照)上でそのまま呼び出しており、goAsyncの実行時間制限内に収まるよう`GeminiClient.NOTIFICATION_TIMEOUT_MILLIS`(接続・読み込み各4秒、合計最大8秒程度)を設定しています。タイムアウト・APIエラー時も通知自体は必ず表示し、本文に「AI要約: 取得に失敗しました」と明記してフォールバックします(通知が握りつぶされてユーザーが気づけない状態を避けるため)。**キャッシュ**: 通常の期限到達時のみ新規にGeminiを呼び出し、結果を`Task.aiCachedResponse`(`TaskDao.updateAiCachedResponse`)へ保存します。`ReminderScheduler.scheduleSnooze`経由のスヌーズ再通知では常にこの`aiCachedResponse`を再利用し(初回呼び出しが失敗してキャッシュが無い場合を含め)、APIを再度呼び出しません(同じプロンプトに対して通知のたびにAPIを呼び直さないため)。初回呼び出しが失敗した場合、スヌーズ後の通知はAI要約なしの通常の通知になります(失敗した旨は初回の通知で既に示しているため)。`TaskViewModel.updateTask`は`TaskEdits.aiPrompt`/`aiUseWebSearch`/`aiUseUrlContext`のいずれかが変更された場合に`aiCachedResponse`/`aiCachedSources`を`null`にクリアします(プロンプトや使用ツールを変えたのに古い結果を使い回さないため)。通知履歴(`NotificationLog`)の`triggerCondition`にはAI呼び出しの成否を`(AI要約: 成功)`/`(AI要約: 失敗)`として付記します。設定画面のデバッグセクションには「AIテスト実行」ボタン(`GeminiTestDialog`)があり、通知の発火を待たずに`TaskViewModel.testGeminiPrompt`で任意のプロンプトを試せます(タイムアウトは`GeminiClient.TEST_TIMEOUT_MILLIS`=15秒と、通知経由より長めに設定)。`TaskDetailDialog`(確認画面)では`aiPrompt`と直近の`aiCachedResponse`を読み取り専用で表示します。バックアップのJSON形式にも`aiPrompt`/`aiCachedResponse`が他の任意フィールドと同様に含まれます(旧形式のファイルにはキー自体が無いため`JSONObject.isNull`により後方互換を保っています)。**組み込みツール(Web検索・URLコンテキスト)**: `Task.aiUseWebSearch`/`Task.aiUseUrlContext`(いずれもBoolean、既定`false`)で、Gemini APIの組み込みツール`google_search`(Web検索によるグラウンディング)・`url_context`(プロンプト中のURLの内容を取得してコンテキストに使う)をタスクごとに個別に有効化できます。`EditTaskDialog`の「AIプロンプト」直下・設定画面の「AIテスト実行」(`GeminiTestDialog`)双方で共通の`AiToolCheckboxes`(2つの`Checkbox`)から選択します。`GeminiClient.generateContent`は有効なツールぶんだけ`tools`配列(各要素は`{"google_search": {}}`のように、protoのフィールド名(スネークケース。generativelanguageのv1beta `Tool`メッセージの`google_search`/`url_context`フィールドに対応し、protobufのJSONパーサはこのスネークケース表記もcamelCase表記も受理するため、あえてproto定義そのままの表記にしている)をキーに持つ空オブジェクト)を`generateContent`のリクエストボディに追加します。レスポンス側は`candidates[0].groundingMetadata.groundingChunks`(`google_search`。各チャンクの`web`オブジェクトから`uri`/`title`を取る)と`candidates[0].urlContextMetadata.urlMetadata`(`url_context`。`urlRetrievalStatus`が`URL_RETRIEVAL_STATUS_SUCCESS`のエントリのみ対象とし、`retrievedUrl`を取る。取得失敗〈`ERROR`/`UNSAFE`等〉でも`retrievedUrl`自体は返るため、ステータスを見ずに使うと実際にはコンテキストとして使われなかったURLを出典として表示してしまう)から出典を集め、`GeminiClient.Source(title, uri, origin)`(`origin`は`GeminiClient.SourceOrigin`の`WEB_SEARCH`/`URL_CONTEXT`)のリストとして`GeminiClient.Result.Success.sources`に含めます。抽出はすべて`opt*`系のみを使うため、フィールド名の解釈を誤っていても例外にはならず出典が空になるだけで応答本文自体は失われません。`sourceLabel()`(`MainActivity.kt`内)が各出典を「出典: タイトル」の形でラベル化します。`GeminiClient.encodeSources`/`decodeSources`で`Task.aiCachedSources`(JSON配列文字列、例`[{"title":"...","uri":"...","origin":"WEB_SEARCH"}]`)との相互変換を行い、`ReminderReceiver`は`taskDao.updateAiCachedResponse(taskId, response, sources)`で応答本文とあわせてキャッシュします。Googleの利用規約上、Search grounding利用時は出典(検索候補)の表示が求められますが、通知(`NotificationCompat.BigTextStyle`)はプレーンテキストのみのためリンク付きのHTML表示ができず、**出典は`TaskDetailDialog`(確認画面)・`GeminiTestDialog`にのみクリック可能なリンクとして表示し、通知本文には含めません**。`TaskViewModel.updateTask`は`aiPrompt`に加えこの2つのツール設定が変わった場合も`aiCachedResponse`/`aiCachedSources`を`null`にクリアします(条件が変われば古い結果・出典を使い回さないため)。バックアップのJSON形式にも`aiUseWebSearch`/`aiUseUrlContext`/`aiCachedSources`が含まれ、旧形式のファイルには無いキーのため`optBoolean`(既定`false`)・`isNull`で後方互換を保っています。Web検索の組み込みツールは通常のトークン課金とは別に無料枠が設定されていますが、モデル・料金プラン(無料/有料)によって条件が異なり、Geminiの料金体系自体も変わりやすいため、具体的な数値をハードコードせず設定画面の「AI連携」セクションでは「無料枠を超えると課金が発生するので[Gemini APIの料金ページ](https://ai.google.dev/gemini-api/docs/pricing)で確認すること」とだけ注記しています。**マップ(`google_maps`)は使用不可**: 地図データを使う用途が無いため、Gemini APIの組み込みツール`google_maps`によるグラウンディングは使用不可にしています。`EditTaskDialog`・`GeminiTestDialog`の`AiToolCheckboxes`にマップの選択肢は無く、`GeminiClient.generateContent`も`useMaps`引数自体を受け付けません(組み合わせ制約だった`MODELS_WITHOUT_SEARCH_AND_MAPS_COMBO`も、対応するツール自体が無くなったため削除済み)。`Task.aiUseMaps`カラムは既存端末のデータ・バックアップとの互換性のためだけに残しており、UIから`true`にする経路は無く、`TaskViewModel.updateTask`はタスクを保存するたびに(このマップ使用不可より前に`true`で保存されていたタスクを含め)`aiUseMaps`を`false`に正規化し、そのタスクのAI応答キャッシュ(`aiCachedResponse`/`aiCachedSources`)も古い条件のものとしてクリアします。`GeminiClient.SourceOrigin`にも`MAPS`は存在しません(過去に保存された`aiCachedSources`に`"origin":"MAPS"`が残っていた場合、`decodeSources`は不明な`origin`として`WEB_SEARCH`扱いにフォールバックします)。
