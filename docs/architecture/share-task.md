# 共有によるタスク追加

**共有によるタスク追加**: `app/src/main/java/com/toshi0907/oboetotte/share/ShareReceiverActivity.kt`が実体です。`AndroidManifest.xml`で`ACTION_SEND`/`ACTION_SEND_MULTIPLE`(いずれも`mimeType="*/*"`で写真に限らず任意のファイル形式を受け付ける)のintent-filterを持つ`exported="true"`のActivityとして登録しており、他のアプリの共有メニューにOboetotteが表示されます。確認・編集画面は挟まず、起動直後に`taskDao.insert`で「タスク(`yyyy/MM/dd HH:mm`形式のローカル日時)」という名前・デフォルト期限(`TaskViewModel.DEFAULT_DUE_DELAY_MILLIS`、登録時刻の1時間後。他のタスク登録と共有するため`private`から公開に変更)の新規タスクを即座に作成し`ReminderScheduler.schedule`を呼びます。`Intent.EXTRA_STREAM`から取得した共有ファイルの`Uri`(`ACTION_SEND`は単一、`ACTION_SEND_MULTIPLE`は複数)は、複数あってもすべて同じ1件の新規タスクへの添付ファイルとして`AttachmentStorage.copyToStorage`(既存の添付ファイル追加と同じ経路)で端末内にコピーし`taskAttachmentDao.insert`で保存します(1ファイルあたり100MBの上限・空き容量の確保〈`docs/architecture/task-attachments.md`参照〉を超えたファイルは`StorageLimitException`を捕捉してスキップし、他のファイルの添付は続行。完了時のToastに添付できなかった件数を含める)。`Intent.EXTRA_TEXT`から取得した共有テキストは、trim後の文字列全体が`android.util.Patterns.WEB_URL`に完全一致すればURL共有とみなし`normalizeUrl()`(`MainActivity.kt`内、他のタスク登録〈`EditTaskDialog`〉と共有するため`private`から公開に変更)を通してタスクの`url`に、一致しなければテキスト共有とみなしそのまま`memo`に格納します(ファイルと同時に共有された場合も両方保存します)。画面には何も表示せず(`Theme.Oboetotte.SnoozeDialog`の透過テーマを流用)、保存完了後に`Toast`で結果(添付件数・URL/メモの別を含む)を通知して`refreshTaskWidget`を呼んでから`finish()`します。所属リストは指定できないため常に`listId = null`(リスト未登録)になります。

**共有ファイルUriの検証(Issue #134)**: このActivityは`exported="true"`で他アプリから無操作で起動できるうえ、`AttachmentStorage.copyToStorage`の`openInputStream`はアプリ自身の権限で実行されるため、`file:///data/data/<自アプリ>/databases/...`のようなUriを渡されると内部ファイル(DB・SharedPreferences・他タスクの添付など)が添付として取り込まれ、添付を開く操作やバックアップ経由で流出しうる。そのため`copyToStorage`側で`content://`以外のスキームと、自アプリのContentProvider(`${applicationId}.fileprovider`、および`PackageManager.resolveContentProvider`で自パッケージと判定されるもの。`userId@authority`形式のユーザーID部分は除いて判定)を指すUri、および自アプリが`takePersistableUriPermission`で永続的なアクセス権を持つUri〈クラウド自動バックアップの保存先フォルダ等〉配下を指すUriを拒否し`null`を返す(詳細は`docs/architecture/task-attachments.md`)。`ShareReceiverActivity`はタスク作成より前に各Uriのコピーを`try/catch`で囲んで実行し、拒否(`null`)・例外のいずれでもそのファイルだけスキップして処理を続行し、Toast・操作ログに「添付失敗N件」を付記する。取り込めたファイルが0件かつ共有テキストも無い場合はタスクを作成せず「共有されたファイルを取り込めませんでした」とToast表示して終了する(他アプリから無操作で空タスク・リマインダーを量産されないようにするため)。コピー済みでまだ`taskAttachmentDao.insert`まで到達していないファイルは`unpersisted`リストで追跡し、処理がキャンセルされた場合(Activity破棄による`lifecycleScope`のキャンセル)やタスク・添付のDB登録が失敗した場合は`finally`で削除して、DBに紐づかない実体ファイルが残らないようにしている。
