# ホーム画面ウィジェット

**ホーム画面ウィジェット**: `app/src/main/java/com/toshi0907/oboetotte/widget/TaskWidget.kt`にJetpack Glance(`androidx.glance:glance-appwidget`。既存のAndroidX依存と同じく`google()`リポジトリ経由のためGitHub Actionsでのみビルド確認可能)で実装しています。`TaskWidget`(`GlanceAppWidget`)の`provideGlance`が毎回`AppDatabase.getInstance(context).taskDao().getAll().first()`で最新のタスク一覧を取得し、`parentTaskId == null && !it.isDone`でトップレベルの未完了タスクのみに絞り込んだ上で、後述の「表示するリスト」設定でさらに絞り込んで表示します(`TaskDao.getAll`の`ORDER BY`をそのまま使うため、メイン画面と同じ「期限が近い順」で並びます)。各行にはタイトルに加え、期限があれば期限日時(メイン画面と同じ`formatDueAt`の書式。`MainActivity.kt`で`internal`化してウィジェット側から再利用)を表示します。期限日時の文字色は、メイン画面(`MainActivity.kt`の`TaskTreeRow`)と同じく期限切れは赤系・当日期限(`Task.isOverdue`/`Task.isDueToday`。いずれも`MainActivity.kt`のトップレベル拡張関数をウィジェット側から再利用)は緑系で強調します(`TaskWidget.kt`内の`dueTextColor`関数)。ウィジェット(Jetpack Glance)では`MaterialTheme.colorScheme`を参照できないため、メイン画面の`MaterialTheme.colorScheme.error`ではなく`ui/theme/Color.kt`に追加した固定色(`Red40`/`Red80`。当日期限の`Green40`/`Green80`と同じ考え方で、ダイナミックカラーの影響を受けない)を使い、赤・緑いずれも濃淡2種類を持ちます。どちらの濃淡を使うかは背景色設定(後述の`WidgetBackground`)ごとに選び、`WHITE`は常に淡色向け(`Red40`/`Green40`)、`BLACK`は常に濃色向け(`Red80`/`Green80`)、`TRANSPARENT`は端末のダークテーマ設定(`Context.resources.configuration.uiMode`から判定。メイン画面の`isSystemInDarkTheme()`に相当)に従います。URLがある場合、表示をコンパクトに保つためURL文字列そのものではなく「リンク」というラベル(`TaskWidget.kt`内の`LINK_LABEL`定数)をタップ可能であることがわかるようリンクテキスト(メイン画面のタスク詳細でのURL表示と同じ考え方で、テーマのプライマリカラー相当の固定色`Purple40`/`Purple80`+下線`TextDecoration.Underline`。背景・枠線・角丸などボタンを想起させる装飾は持たない。Issue #109)で表示し、期限がある行は`Row`で期限日時と同じ行にラベルを並べ、期限が無い場合のみ単独の行に表示します。以前はボタン状(背景色`Purple40`固定・白文字・角丸)の表示でしたが、期限テキストとの縦方向の余白の違いによりレイアウトが揃わない問題があったため変更しました。リンクテキストの濃淡(`Purple40`/`Purple80`)は、期限の色分け(`dueTextColor`関数)と同じ`useDarkPalette`関数で判定し、背景色設定ごとに選びます(`WHITE`は常に淡色向け`Purple40`、`BLACK`は常に濃色向け`Purple80`、`TRANSPARENT`は端末のダークテーマ設定に従う)。行(タイトル・期限部分)をタップすると`actionStartActivity<MainActivity>()`でアプリを開くのみで、ウィジェット上での完了操作などは行いませんが、「リンク」ラベル部分だけは個別のクリックアクションを持ち、タップするとブラウザ等でURLを直接開きます(Glanceは内側の要素に設定したクリックアクションが外側のクリックアクションより優先されるため、行全体を包む`Column`に「アプリを開く」を、リンクの`Text`だけに「URLを開く」を設定することで両立しています)。`androidx.glance.action.actionStartActivity`には任意の`Intent`を渡せるオーバーロード(`ComponentName`または`reified`な`Activity`型のみ)が無いため、リンクのURLを開く処理は`ActionCallback`(`widget/TaskWidget.kt`内の`OpenTaskUrlAction`)+`actionRunCallback<OpenTaskUrlAction>(actionParametersOf(URL_PARAM_KEY to url))`で行い、`onAction`内で`Context.startActivity(Intent(Intent.ACTION_VIEW, ...))`(`FLAG_ACTIVITY_NEW_TASK`付き。通知の「リンクを開く」ボタンと同じ考え方)を呼び出します。開けるアプリが無い場合(`ActivityNotFoundException`)は`MainActivity`のURL項目タップ時と同じ文言を`Toast`で表示します(`onAction`はメインスレッドで呼ばれるとは限らないため`withContext(Dispatchers.Main)`に切り替えます)。表示は自動更新されないため、`TaskViewModel`の`addTask`/`toggleDone`/`updateTask`/`deleteTask`/`addSubtask`と`TaskCompletion.complete`の末尾で`refreshTaskWidget(context)`(`widget/TaskWidgetUpdater.kt`内のトップレベル関数)を呼び、タスクに変更があるたびに再描画をトリガーしています(`TaskCompletion.complete`はアプリ内・通知の「完了」アクションの両方から呼ばれるため、通知経由の完了もウィジェットに反映されます)。`refreshTaskWidget`は内部で`TaskWidget().updateAll(context)`を呼ぶだけの薄いラッパーですが、`updateAll`が投げた例外を`CancellationException`以外は`Log.e("TaskWidget", ...)`で握りつぶします。ウィジェットの再描画に失敗しても、直前に完了している呼び出し元のDB書き込み自体を失敗させたくないためで、もし実機でウィジェットが更新されない場合はlogcatをタグ`TaskWidget`で確認すると原因を切り分けられます。`AndroidManifest.xml`には`TaskWidgetReceiver`(`GlanceAppWidgetReceiver`)を`android:exported="true"`で登録し、ウィジェット情報は`res/xml/task_widget_info.xml`(`updatePeriodMillis`はOS側の最小値である30分に設定。`initialLayout`はGlanceライブラリ組み込みの`@layout/glance_default_loading_layout`をそのまま使用)で定義しています。**背景色**: `WidgetBackground`(`widget/WidgetBackground.kt`内の`enum class`。`TRANSPARENT`/`WHITE`/`BLACK`の3値で、`TRANSPARENT`は背景色・文字色とも上書きせず従来の見た目のまま)をウィジェットのインスタンスごとに個別選択できます。`task_widget_info.xml`の`android:configure`で`widget/TaskWidgetConfigureActivity.kt`を指定しており、ホーム画面にウィジェットを追加する際にシステムから自動的に起動されます(`ACTION_APPWIDGET_CONFIGURE`のintent-filterも`AndroidManifest.xml`に登録)。この設定画面は`AppWidgetManager.EXTRA_APPWIDGET_ID`で対象のウィジェットIDを受け取り、`AlertDialog`+`FilterChip`(縦に長くなるため`Modifier.verticalScroll`でスクロール可能)で背景色・表示するリスト・後述の表示フィルタを選択させ、「追加」確定時に`GlanceAppWidgetManager(context).getGlanceIdBy(appWidgetId)`で`GlanceId`に変換した上で`updateAppWidgetState(context, glanceId) { prefs -> prefs[TaskWidget.BACKGROUND_KEY] = background.name; prefs[TaskWidget.LIST_FILTER_KEY] = listFilter; prefs[TaskWidget.DISPLAY_FILTER_KEY] = displayFilters.map { it.name }.toSet() }`(`androidx.glance.appwidget.state`)により選択値を保存し、`refreshTaskWidget(context)`で再描画をトリガーしてから`RESULT_OK`で終了します(`GlanceAppWidget`には単一インスタンスだけを対象にした`update`関数は無いため、内部的には全ウィジェットインスタンスを対象にする`updateAll`を呼びますが、他のインスタンスは自身の設定を読み直すだけで見た目は変わりません)(何も選ばず閉じた場合は`RESULT_CANCELED`のままとなり、システムがウィジェットの追加自体を取り消します)。`TaskWidget`は`override val stateDefinition = PreferencesGlanceStateDefinition`を指定しており、これによりGlanceがウィジェットインスタンス(`GlanceId`)ごとに`Preferences`用のDataStoreを自動的に用意・永続化してくれるため、アプリ側で独自のキー管理を行う必要はありません。`provideGlance`側は`currentState<Preferences>()[TaskWidget.BACKGROUND_KEY]`で自インスタンスの選択値を読み出し、`WidgetBackground.fromName()`で復元して背景色(`GlanceModifier.background()`)と文字色(`TextStyle(color = ColorProvider(...))`)に反映します。**表示するリスト**: メイン画面のリストフィルタ(Issue #56で追加した「すべて」/「リスト未登録」/各リスト)と同じ選択肢を、`TaskWidget.LIST_FILTER_KEY`(`stringPreferencesKey`)としてウィジェットインスタンスごとに保存します。値は「すべて」を表す`TaskWidget.ALL_LISTS_VALUE`(`"ALL"`。キー未設定の場合もこれと同じ扱い)、「リスト未登録」を表す`TaskWidget.UNASSIGNED_LIST_VALUE`(`"UNASSIGNED"`。`listId == null`のタスクのみ)、またはタスクの`listId`を文字列化した値のいずれかです。`TaskWidgetConfigureActivity`は`AppDatabase.getInstance(context).taskListDao().getAll().first()`(`LaunchedEffect(Unit)`内)でリスト一覧を取得し、各リストを`FilterChip`として選択肢に並べます。`provideGlance`側は`prefs[LIST_FILTER_KEY]`を読み出し、未完了のトップレベルタスク一覧をさらに絞り込んでから表示します。**表示フィルタ**: メイン画面の表示フィルタ(`TaskDisplayFilter`。詳細は`docs/architecture/task-list-screen.md`)と同じ「リンクを含む」(`HAS_URL`)・「今日期限・期限切れ」(`DUE_TODAY_OR_OVERDUE`)を、`TaskWidget.DISPLAY_FILTER_KEY`(`stringSetPreferencesKey`。値は選択中の`TaskDisplayFilter.name`の集合)としてウィジェットインスタンスごとに複数選択で保存します(メイン画面と同じくOR判定。空集合・キー未設定は「絞り込みなし」)。`provideGlance`側は表示するリストで絞り込んだ後のタスク一覧に対してこのフィルタをさらに適用し、合致するタスクのみを表示します。フィルタ1つとタスクが合致するかどうかの判定(`TaskDisplayFilter.matches(task, nowMillis)`。`TaskViewModel.kt`内のトップレベル拡張関数)はメイン画面(`MainActivity.kt`の`TaskScreen`)と共通で、`Task.isOverdue`/`Task.isDueToday`を使う実体もここに1箇所だけ実装しています。判定基準の「現在時刻」はウィジェット描画のたびに取得する`System.currentTimeMillis()`です。`LazyColumn`の`items(filteredTasks, itemId = ...)`には、Jetpack Glanceの既知の不具合(Google Issue Tracker #240300611)として、`itemId`が変わらないまま一部フィールドだけを更新した場合に再描画が反映されないケースがあるため、`itemId`にはタスクIDだけでなく表示内容(タイトル・期限・URL・`isOverdue`/`isDueToday`の判定結果)のハッシュ値も組み込んだ複合キー(`TaskWidget.kt`内のprivate拡張関数`Task.widgetItemId(nowMillis)`。上位32bitにタスクID、下位32bitに表示内容のハッシュ値を詰めた`Long`)を使っています(Issue #105。期限のみを変更した場合にウィジェットの表示が更新されないことがある不具合の対応)。`isOverdue`/`isDueToday`は他のフィールドが変わらないまま時刻の経過だけで結果が変わる(期限切れ・当日期限への切り替わり)ため、これらもハッシュに含めることで期限の色分け表示が同じ不具合で更新漏れしないようにしています。それでも実機で期限のみの変更がウィジェットに反映されないケースが再現したため(Issue #111)、原因調査・手動復旧を容易にする目的で、ウィジェット上部に**最終更新日時**と**更新ボタン**を追加しています。最終更新日時は`TaskWidget.LAST_UPDATED_AT_KEY`(`longPreferencesKey`。他の設定値と同じく`PreferencesGlanceStateDefinition`によりウィジェットインスタンスごとに保持)にepoch millisで保存し、`provideGlance`側で「最終更新: yyyy/MM/dd HH:mm:ss」形式(`TaskWidget.kt`内のprivate関数`formatLastUpdatedAt`。メイン画面等で使う`formatDueAt`は秒を含まないため、原因調査で秒まで区別できるよう専用の書式を用意)に整形して表示します(未設定の場合は「最終更新: まだ更新していません」)。この値は`refreshTaskWidget`(`TaskWidgetUpdater.kt`)が`updateAll`を呼ぶ前に、`GlanceAppWidgetManager(context).getGlanceIds(TaskWidget::class.java)`で列挙した既存の全ウィジェットインスタンスそれぞれに対し`updateAppWidgetState`で現在時刻を書き込む形で更新するため、`refreshTaskWidget`の全ての呼び出し元(タスクの追加・編集・期限変更・削除・完了切り替え、および後述の更新ボタン)で共通して更新されます。更新ボタンは、リンクラベル(`LINK_LABEL`)と全く同じ実装パターンで、クリックアクション付きの`Text`(「[更新]」というラベルに`GlanceModifier.clickable(actionRunCallback<RefreshTaskWidgetAction>())`とタップ領域確保のためのパディングを設定し、`linkTextStyle`〈リンクラベルと同じ色+下線〉をそのまま使い回したもの)として実装しています(Jetpack Glanceの`GlanceAppWidget`モジュールに用意されている`Button`コンポーザブルは使っていません)。タップすると`ActionCallback`(`TaskWidget.kt`内の`RefreshTaskWidgetAction`)が`refreshTaskWidget(context)`を呼び出し、DBからの再取得(`provideGlance`は呼ばれるたびに常にDBから最新のタスク一覧を取得するため、既存のロジックがそのまま「再取得」を兼ねます)・強制的な再描画・最終更新日時の更新をまとめて行います。`updateAll`の失敗時は`refreshTaskWidget`内の既存の`Log.e("TaskWidget", ...)`がそのままログ出力を担うため、更新ボタン専用の追加のエラーハンドリングは不要です。
