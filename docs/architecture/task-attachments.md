# タスクへのファイル添付

**タスクへのファイル添付**: `data/TaskAttachment`(`id`/`taskId`/`fileName`〈元のファイル名〉/`storedFileName`〈保存用のUUIDベースのファイル名〉/`mimeType`/`sizeBytes`/`createdAt`)として、1タスクに複数のファイルを添付できます(`TaskAttachmentDao`、`AppDatabase`バージョン10→11の`MIGRATION_10_11`)。ファイルの実体(バイト列)は`attachment/AttachmentStorage`が端末内の`filesDir/attachments/`配下にコピーして保存し、Room側は`storedFileName`のみを保持します。選択時に渡された`Uri`そのものには依存しないため、元ファイルが後から削除・移動されても添付は残ります。**`TaskAttachment.taskId`はタスク自身の`Task.id`ではなく`Task.attachmentGroupId()`(`Task.kt`内の拡張関数、`seriesId ?: id`)を格納します**(`AppDatabase`バージョン13→14の`MIGRATION_13_14`で`tasks.seriesId`列を追加)。繰り返しタスクが完了して次回分が生成されるたびに新しい`Task.id`を持つ行が作られる(`docs/architecture/repeat-tasks.md`参照)ため、`taskId`にタスク自身の`id`をそのまま使うと完了・次回生成のたびに添付ファイルが「消えた」ように見えてしまう不具合があり、その対策として導入しました。`TaskDetailDialog`/`EditTaskDialog`の添付ファイル一覧は`allAttachments.filter { it.taskId == task.attachmentGroupId() }`で絞り込むため、同じ繰り返しシリーズの全インスタンス(過去の完了済み分・現在未完了の分すべて)が常に同じ添付ファイル集合を参照し、どのインスタンスから追加・削除してもシリーズ全体に反映されます。`TaskViewModel.addAttachment(task, uri)`(`Dispatchers.IO`でコピー、`taskId = task.attachmentGroupId()`で保存)/`deleteAttachment(attachment)`で操作し、`deleteTask`は削除後に`TaskDao.countByAttachmentGroup(groupId)`で同じシリーズの他のインスタンスがまだ残っているか確認し、残っていなければ(=シリーズ最後の1件を削除した場合のみ)そのグループの添付ファイル(DB行+実体)を削除します(既存の非FK方針と同様、サブタスクへのカスケードはありません)。UI側は`EditTaskDialog`の「添付ファイル」セクションの「ファイルを追加」ボタンをタップすると、まず選択方法を選ぶダイアログ(「全ファイルから選択」/「写真から選択」)が開きます。「全ファイルから選択」は`ActivityResultContracts.OpenMultipleDocuments()`(mime `*/*`)、「写真から選択」は`ActivityResultContracts.PickMultipleVisualMedia()`(`PickVisualMediaRequest`に`ActivityResultContracts.PickVisualMedia.ImageOnly`を指定、Android標準のフォトピッカーで画像のみを複数選択可能)を使い分けます。一覧の各行(`AttachmentRow`)はファイル名+サイズを表示し、`mimeType`が`image/`で始まる場合は`BitmapFactory`でダウンサンプリングデコードしたサムネイル(`AttachmentThumbnail`、`produceState`+`Dispatchers.IO`)を、それ以外は📎の汎用マーカーを表示します。行タップで`AttachmentStorage.openIntent(context, attachment)`(`androidx.core.content.FileProvider`経由、authorityは`${applicationId}.fileprovider`、`res/xml/file_paths.xml`で`filesDir/attachments/`を公開)が組み立てる`ACTION_VIEW` Intentを起動して外部アプリで開き、「削除」ボタンでDB行とファイル実体の両方を削除します。**添付ファイルのプレビュー**: `TaskDetailDialog`(確認画面)の添付ファイル一覧では、`AttachmentRow`の直下に`AttachmentPreview`を並べて表示し、`mimeType`が`image/`で始まる画像は`decodeThumbnail(file, maxSize = 1080)`でダウンサンプリングした大きめのビットマップをインライン表示、`application/pdf`は`renderPdfPages()`(`android.graphics.pdf.PdfRenderer`、追加ライブラリ不要の標準API)で全ページを画面幅相当の解像度のビットマップへ変換し、縦に並べて表示します(ページ数が多いPDFでも全ページ表示するため、`TaskDetailDialog`の`verticalScroll`でまとめてスクロールします)。それ以外の形式はプレビュー非対応のため`AttachmentPreview`は何も描画せず、`AttachmentRow`のタップによる外部アプリでの表示のみとなります。`EditTaskDialog`側の一覧には`AttachmentPreview`を表示しません(プレビューは確認画面のみの機能)。画像・PDFいずれのプレビューにも`Modifier.background(Color.White)`で背景色を白固定しています(ダークテーマ端末で透過部分のあるPDF・画像をプレビューすると、透過部分に暗い背景色が透けて文字等が読めなくなることがあったため)。
