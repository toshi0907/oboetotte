# 繰り返しタスク

**繰り返しタスク**: `repeatRule`は`RepeatRule`(`TaskViewModel.kt`内の`object`)で定義した`"DAILY"`/`"WEEKLY"`/`"WEEKLY_DAYS"`/`"MONTHLY"`/`"AFTER_COMPLETION"`のいずれかです。期限を起点にしたカスタム間隔(2日おき等)は未対応です(完了日を起点にした日数指定は後述の`AFTER_COMPLETION`で対応)。`WEEKLY_DAYS`(UI表示「毎週(曜日)」)は、`Task.repeatDaysOfWeek`にISO-8601の曜日番号(月曜=1〜日曜=7)をカンマ区切りで保存し(`RepeatRule.parseDaysOfWeek`/`formatDaysOfWeek`で相互変換)、複数曜日を選択できます。`EditTaskDialog`で「毎週(曜日)」を選択すると月〜日の`Checkbox`が7つ表示され、最低1つ選択しないと(`selectedDays.isEmpty()`)保存ボタンが無効化されます。タスクを完了にする処理は`TaskCompletion.complete(context, task)`(`TaskCompletion.kt`、アプリ内・通知の両方から共通利用)に集約しており、`repeatRule`と`dueAt`が両方設定されていれば(`WEEKLY_DAYS`の場合はさらに`repeatDaysOfWeek`が空でなければ)`RepeatRule.nextDueAt()`(`TaskViewModel.kt`の`RepeatRule`内、`java.time`でローカルタイムゾーンの日時を加算。カレンダー表示の将来の予定の計算と共通利用)で次回の期限を計算し、同じタイトル/リスト/親/繰り返しルール/曜日設定を持つ未完了の新規タスクを`taskDao.insert`で生成します。`WEEKLY_DAYS`の次回期限は、現在の期限日の翌日から最大7日分を順に調べ、選択された曜日のうち最も近い日(同じ週内も含む)を採用します。`dueAt`が未設定の繰り返しタスクは、完了しても次回分は生成されません。次回分の生成時は`nextTask.seriesId = task.attachmentGroupId()`(`Task.attachmentGroupId()`、`Task.kt`内の拡張関数で`seriesId ?: id`)を設定して引き継ぎます。これにより繰り返しシリーズの全インスタンス(初回・完了済みの過去分・現在未完了の分すべて)が同じ`seriesId`(初回インスタンスのみ`seriesId`が`null`のままなので、その場合は自分自身の`id`)を共有し、添付ファイルの紐付け(`docs/architecture/task-attachments.md`参照)が繰り返しのたびに途切れず連動し続けます。

**完了後に繰り返す(`AFTER_COMPLETION`)**: UI表示「完了後」。期限ではなく完了日を起点に、`Task.repeatIntervalDays`(1〜999日、`RepeatRule.INTERVAL_DAYS_RANGE`。DBバージョン25の`MIGRATION_24_25`で追加した列)日後を次回の期限にします。計算は`RepeatRule.nextDueAtAfterCompletion()`で、完了日時(`TaskCompletion.complete`内で`setDone`に渡した`completedAt`)のローカル日付に日数を加え、時刻は元の`dueAt`の時刻を引き継ぎます(期限を過ぎて完了した場合も実際の完了日が起点)。他のルールと同じく`dueAt`未設定なら次回分は生成せず、`repeatIntervalDays`が範囲外・未設定の場合も生成しません。`EditTaskDialog`では「完了後」選択時のみ日数の入力欄を表示し、範囲内の整数でなければ保存ボタンを無効化します。`TaskViewModel.updateTask`は他のルールに切り替えた際に`repeatIntervalDays`をnullへ正規化します。次回の期限が完了するまで決まらないため、カレンダー表示の将来の予定(`SUPPORTED_REPEAT_RULES`)には含めません。ローカル/クラウドバックアップでは`repeatIntervalDays`キーとして書き出し、キーの無い旧形式・範囲外の値はnullとして取り込みます。
