# 通知履歴(デバッグ)

**通知履歴(デバッグ)**: `data/NotificationLog`(`id`/`triggeredAt`〈発動時刻、epoch millis〉/`taskTitle`〈発動時点のタスクタイトル〉/`triggerCondition`〈トリガとなった条件を表す文字列〉)として、実際に発火した通知の履歴を記録します(`NotificationLogDao`、`AppDatabase`バージョン11→12の`MIGRATION_11_12`)。記録対象は期限日時通知(`ReminderReceiver`。通常の期限到達は`triggerCondition = "期限到達"`、`ReminderScheduler.scheduleSnooze`経由のスヌーズ再通知は`"スヌーズ経由の再通知"`)と位置情報通知(`GeofenceReceiver`。到着/離脱と保存済みの場所名・半径を含む文字列)で、いずれも通知を実際に表示した直後に記録します。テスト通知(`ReminderScheduler.scheduleTestNotification`)は記録対象外です。`ReminderScheduler`の`pendingIntentFor(context, taskId, isSnooze)`は`EXTRA_IS_SNOOZE`をIntentのextraとして持たせており、`schedule`(通常)/`scheduleSnooze`(スヌーズ)のどちらが最後に呼ばれたかで`ReminderReceiver`が発火理由を判定します(`PendingIntent.FLAG_UPDATE_CURRENT`により同じtaskId=同じrequestCodeのPendingIntentのextrasが都度上書きされる)。`NotificationLogDao.insertAndTrim(log, limit = 200)`(Kotlinのデフォルトメソッド+`@Transaction`)が挿入のたびに直近200件を超える古い履歴を自動削除し、無制限にDBが肥大化しないようにしています。`TaskViewModel.notificationLogs: StateFlow<List<NotificationLog>>`(発動時刻の降順)として公開し、設定画面の「通知履歴」ボタンから開く`NotificationLogDialog`が新しい順に一覧表示します。バックアップのエクスポート/インポート対象には含めていません(デバッグ用の実行時ログであり、復元して意味のあるデータではないため)。
